# Security: Token Remediation Guide

You had tokens in `.env.local` that may have been exposed (e.g., shared in chat). Follow these steps to regenerate and reconnect them safely.

---

## 1. Vercel Tokens

### VERCEL_OIDC_TOKEN (remove — do not store)
- **What it is:** Short-lived OIDC token auto-generated by Vercel CLI during login.
- **Action:** **Remove it from `.env.local`.** It should never be stored—Vercel CLI creates it per session.
- **Status:** Already removed from your `.env.local` template below.

### VERCEL_TOKEN (deployment token)
- **What it is:** Long-lived token for `npx vercel --prod` deploys.
- **Regenerate:** Go to [vercel.com/account/tokens](https://vercel.com/account/tokens) → **Create** a new token → **Revoke** any old tokens you may have shared.
- **Reconnect:** Add the new token to `.env.local`:
  ```
  VERCEL_TOKEN=your_new_token_here
  ```
- **Note:** Only needed for local CLI deploys. Vercel deploys from GitHub use GitHub integration, not this token.

---

## 2. Cloudflare Images (VITE_CLOUDFLARE_IMAGES_ACCOUNT)

- **What it is:** Your Cloudflare Images account hash (e.g., `e2AbHsbDF0AuG8qYIMyk4A`).
- **Can you regenerate?** **No.** Cloudflare does not allow regenerating this—it’s tied to your account.
- **Risk level:** **Low.** This hash appears in public image URLs (`imagedelivery.net/<hash>/...`). The real secrets are your **Cloudflare API keys**, which should never be in frontend code.
- **Action:** Keep using the same hash. Ensure no **Cloudflare API keys** are in `.env.local` or source code. If you ever added an API key, revoke it at [dash.cloudflare.com → My Profile → API Tokens](https://dash.cloudflare.com/profile/api-tokens) and create a new one.

---

## 3. Cloudflare Stream (STREAM_CUSTOMER in source code)

- **What it is:** Customer code in `src/lib/cloudflare-stream.ts` (e.g., `m0bg04f30urm642q`).
- **Risk level:** **Low.** It’s used in public video URLs. Video IDs in the same file are also public.
- **Action:** If you prefer not to expose it in git, it can be moved to an env var. See the optional change in `cloudflare-stream.ts` below.

---

## 4. Formspree (VITE_FORMSPREE_FORM_ID)

- **What it is:** Form ID for the “Start a conversation” form.
- **Regenerate:** Go to [formspree.io](https://formspree.io) → your form → **Settings** → create a new form or reset the form ID if available.
- **Reconnect:** Add to `.env.local`:
  ```
  VITE_FORMSPREE_FORM_ID=your_new_form_id
  ```

---

## 5. Locked Project Password (VITE_LOCKED_PROJECT_PASSWORD)

- **What it is:** Password for password-protected project pages.
- **Regenerate:** Choose a new password.
- **Reconnect:** Add to `.env.local`:
  ```
  VITE_LOCKED_PROJECT_PASSWORD=your_new_password
  ```
- **Vercel:** Add the same value in [Vercel Dashboard → Project → Settings → Environment Variables](https://vercel.com) for Production/Preview.

---

## 6. Protect `.env.local` from future exposure

- `.env.local` is already in `.gitignore` — it will not be committed.
- **Do not** paste `.env.local` contents or tokens into chat, logs, or screenshots.
- Consider adding `.env.local` to `.cursorignore` so it’s not read by AI tools.

---

## Summary checklist

| Token / Secret              | Regenerate? | Where to reconnect                          |
|----------------------------|-------------|---------------------------------------------|
| VERCEL_OIDC_TOKEN         | Remove      | Do not store                                |
| VERCEL_TOKEN              | Yes         | `.env.local`                                |
| VITE_CLOUDFLARE_IMAGES_ACCOUNT | No      | Keep as-is (or re-copy from dashboard)      |
| Cloudflare API keys       | If exposed  | Never in frontend; use server-side only     |
| VITE_FORMSPREE_FORM_ID    | If exposed  | `.env.local` + Vercel env vars              |
| VITE_LOCKED_PROJECT_PASSWORD | Yes      | `.env.local` + Vercel env vars              |
